# Phase 1 — Make the production HTTP server actually run

## Confirmed production problem

The new frontend bundle is live, so commit `be3d46f` was included in the publication. However, the new `server.js` is not controlling production HTTP responses.

Externally verified production behavior on 2026-08-01:

| Request                      |                        Intended |                   Actual |
| ---------------------------- | ------------------------------: | -----------------------: |
| `/privacy`                   | 308 → `/living-trust-framework` |        301 → `/privacy/` |
| `/privacy/`                  | 308 → `/living-trust-framework` |                      200 |
| `/this-route-does-not-exist` |                             404 |                      200 |
| Hashed JS/CSS cache          |                       immutable | `cache-control: private` |
| Brotli/gzip                  |           expected if supported |                   absent |

The same static-style behavior was observed on the custom domain and Replit deployment URL.

This proves the code changes were published but Replit is still serving the Vite output through its static-serving layer instead of routing requests through `server.js`.

Do not repeat local curl tests and claim the production issue is resolved. Diagnose why the published Autoscale deployment is bypassing the server.

## Required investigation

Inspect:

* `.replit`
* `replit.nix`, if present
* `artifact.toml`, if present
* `package.json`
* `server.js`
* Replit deployment/build configuration
* Publishing configuration
* Deployment logs
* Current working directory used at build and runtime
* Build command
* Run command
* Port binding
* Health-check behavior
* Any static deployment configuration still active
* Any conflicting `deploymentTarget`, static output directory or rewrite configuration

Determine whether:

* The existing deployment is still registered internally as Static despite the UI showing Autoscale.
* `.replit` uses the wrong configuration keys.
* Publishing settings override the repository configuration.
* The Run command is ignored.
* `server.js` starts from the wrong working directory.
* Replit detects the Vite project and serves `dist/public` automatically.
* `artifact.toml` continues to force static fallback behavior.
* A new Autoscale deployment must be created instead of republishing the old Static deployment.

Do not guess. Use deployment logs and configuration evidence.



* Read Replit’s `PORT`.

Remove or disable any conflicting static catch-all rewrite that prevents the Node server from receiving requests.
